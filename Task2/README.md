# Задание 2. Разработка сервиса отчетов

## Задача 1. Архитектура подготовки и получения отчетов

Схема - `BionicPRO_C4_reports.drawio`.

Раз в сутки Airflow забирает телеметрию за прошедший день из базы телеметрии (PostgreSQL) и клиентов
с протезами из CRM DB, группирует показатели по пользователю и дню и загружает результат в витрину
ClickHouse. Сервис отчетов (`GET /reports`) читает готовые строки витрины, и не считает на лету.

**Витрина `reports_mart`.** Одна таблица, где в каждой строке лежат показатели одного
пользователя за один день и данные клиента из CRM. Партиции по месяцам, сортировка по `user_id` и
`report_date`, поэтому отчет одного юзера получается быстро.

**Только загруженный период.** После успешной загрузки DAG записывает обработанную дату в
`etl_loaded_periods`. Сервис отдает данные только до этой даты, а если юзер просит период
позже, сообщаем до какой даты есть данные.

**Только свой отчет.** Запрос идет через Auth BFF с access token. Сервис проверяет JWT и роль
`prothetic_user` и берет логин из токена. Запросить чужой отчет нельзя.

## Задача 2. Airflow DAG и витрина

DAG `reports_mart` лежит в `airflow/dags/reports_mart_dag.py` и запускается каждый день в 02:00 UTC.
Цепочка задач `get_period` → `extract_telemetry` и `extract_crm` → `transform` → `load` →
`mark_loaded`. `get_period` берет дни от последнего загруженного до вчерашнего, поэтому пропущенные
запуски догоняются сами. `load` перед вставкой удаляет период из витрины.

Таблицы ClickHouse описаны в `clickhouse/init/01_reports.sql`. Тестовые источники лежат в `sources/`.

Запуск `docker compose up -d --build`, Airflow на `http://localhost:8081` (admin / admin).

## Задачи 3-5. API отчетов, ограничение доступа, кнопка в UI

Сервис отчетов лежит в `reports_api/`, эндпоинт `GET /reports` на `http://localhost:8000`.
Отчет берется из Clickhouse. Необязательные параметры `date_from` и `date_to` это период.

Сервис проверяет подпись JWT по публичным ключам Keycloak и роль `prothetic_user`. Без токена ответ
401, без роли 403.

Для проверки можно войти на `http://localhost:3000` как `prothetic1` с `prothetic123` и нажать Download Report,
в отчете будут два протеза пользователя. Пользователь `user1` с `password123` получит 403.
